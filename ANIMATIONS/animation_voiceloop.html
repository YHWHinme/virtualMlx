sounddevice — the ears & mouth

The single most critical package — every sample enters and leaves through it.

Opens the microphone as a continuous InputStream at 16 kHz mono float32. Every 32 ms a new chunk arrives via callback and is pushed onto a thread-safe queue. On the output side, an OutputStream feeds TTS audio to the speakers in small frames so barge-in checks can interleave between writes.

numpy — the universal glue

Every audio buffer, every tensor conversion, every resample — all numpy, all the time.

Audio chunks arrive as float32 ndarrays. They get accumulated in lists, concatenated into utterances, resampled from 24 kHz → 16 kHz via np.interp, and cast to int16 for WAV encoding. The chime sound itself is synthesized with numpy — sine waves shaped by a Hann-window envelope.

silero-vad — the speech gatekeeper

Decides when you're talking and when you've stopped — nothing downstream fires without it.

Each 32 ms mic chunk is fed to Silero VAD which returns a speech probability (0.0–1.0). Above 0.5 → accumulate audio. Below 0.5 → count silent chunks. After enough silence, the accumulated buffer is sent to Smart Turn for final confirmation. It also runs on the AEC-cleaned audio during TTS playback to detect barge-in.

onnxruntime + transformers — Smart Turn

After silence is detected, Smart Turn v3 confirms whether the speaker is actually done or just pausing mid-sentence. The audio buffer is featurised with WhisperFeatureExtractor (from transformers) and classified by the ONNX model. If probability < 0.5 → keep listening; ≥ 0.5 → send to STT.

moonshine-voice — the ears

mlx-vlm — the brain

Gemma 4 E4B running on Apple Metal via MLX — the core intelligence of the agent.

The transcript is formatted into a chat message list with system prompt (from SOUL.md) and conversation history. apply_chat_template converts it to a prompt string, then stream_generate produces tokens one-by-one in a background thread. Each completed sentence is pushed onto a queue so TTS can start speaking while the LLM is still generating the rest — this is the key to low-latency responses.

kokoro-onnx — the voice

Sentences from the LLM queue are synthesised in pairs (for natural prosody) using Kokoro's ONNX model on CPU. Each synthesis runs in a thread executor so it overlaps with playback of the previous sentence. Output is a float32 numpy array at 24 kHz, ready for the speaker.

sounddevice out + livekit AEC3

sounddevice returns as the output path — this time paired with echo cancellation for barge-in.

TTS audio plays through sd.OutputStream in 4096-sample frames. Between each frame, the mic queue is drained and each chunk is fed through LiveKit's APM (WebRTC AEC3) with the TTS audio as the reference signal. The echo-cancelled mic audio is then checked by Silero VAD — if 5 consecutive chunks show speech above 0.8 probability, the agent is interrupted.
