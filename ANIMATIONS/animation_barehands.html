Webcam + MediaPipe — 21 landmarks per hand

The entire input pipeline. No controllers, no headset — just a camera watching your hands.

Google's MediaPipe HandLandmarker runs in the browser and returns 21 3D landmarks per hand at ~30Hz. The code extracts cursor position (index tip + thumb tip midpoint), hand span (wrist→middle-knuckle, the hand's own yardstick), and per-finger arch ratios that drive every gesture gate.

The Pinch — THE CONTRAST LAW

The primary interaction. Must distinguish a deliberate OK-sign from a closed fist.

A fist also brings the thumb to the index tip — raw gap distance can't tell them apart. The insight: in a correct pinch, the index curls IN to the thumb while the back three fingers ARCH OUT past the knuckle circle. In a fist, all fingers fold in. The contrast (backMean − f8) separates every correct pinch from every impostor.

contrast = backMean − f8 threshold ≥ 0.18 backMean floor ≥ 1.30 aspect < 2.0 → profile regime

Gesture Gates — shape ratios, not pixels

Every gesture gate measures hand shape as ratios against the hand's own span, not screen pixels. This is why they work at any camera distance. Three major gestures beyond the pinch:

THE CLAW
Flash open → claw → aim → hold 2 seconds → snap shut

Gates: mouth ratio > 0.80, per-finger curl ceilings, pinky-out splay, aspect rail
THE CLAP
Palms together, fingers up → sweep board clean

Gates: wrist proximity, handUp > 0.85, was-apart memory
THE THROW
Fling a card across the screen → velocity carry

Gate: peak velocity > 1300px/s (one of few pixel-based gates)
// per-finger arch ratio — distance-proof
const fR = (t, m) => {
  const td = Math.hypot(lms[t].x - W0.x, lms[t].y - W0.y);
  const md = Math.hypot(lms[m].x - W0.x, lms[m].y - W0.y);
  return md > 0 ? td / md : 9;
};
// fR(8,5)=1.6 → finger extended. fR(8,5)=0.8 → folded in.
// Works at any distance because span cancels out.

Physics + Render — glass cards in motion

Every frame: physics(dt) updates positions and velocities, renderModels() draws 3D holograms, renderRings() draws the assistant ring, and pushState() streams the scene to the server. The items[] array is the scene's source of truth — cards, panels, images, models, orbs.

items[] physics(dt) renderModels() renderRings() pushState(now)
main loop — every requestAnimationFrame
// the main loop
function frame(now) {
  if (cam.currentTime !== lastVideoTs) {
    const res = landmarker.detectForVideo(cam, now);
    // → landmarks → cursors → gesture gates
  }
  physics(dt);       // velocity, friction, bounds
  renderModels();   // three.js 3D scenes
  renderRings();    // assistant ring canvas
  pushState(now);   // stream to server ~45Hz
  requestAnimationFrame(frame);
}

Server — state store + command queue

Two in-memory variables. The heartbeat IS the command channel.

server.py is stdlib-only Python — no pip install. It holds _STATE (the tracker's last scene) and _CMDS (queued AI commands). When the tracker POSTs its heartbeat, the server returns up to 8 queued commands in the response. The render page GETs the same state to mirror the scene.

AI Commands — the assistant's hands + eyes

The AI drives the board via POST /cmd — a JSON body with an action from the 13-verb allowlist. The server validates the action, enforces the media airlock (only files inside media/ can stage), and queues the command for the next heartbeat. The AI reads the board back via GET /state or board-state.sh.

three.js — holograms + exploded views

GLB/glTF models from the media airlock get their own three.js scene per item — each with its own WebGL renderer, camera, and canvas. Two modes: solid (PBR with environment map) and hologram (blue wireframe with rim shader). The explode verb separates child meshes along their normals.

GLTFLoader DRACOLoader WebGLRenderer (alpha) ShaderMaterial (holo) applyExplode(sc, tgt)
3D render pipeline — one scene per model item
// two render modes, chosen by folder
function modelModeFor(src, want) {
  if (src.includes('/holo/')) return 'holo';
  return want || 'solid';
}

// explode: separate child meshes along normals
function applyExplode(sc, tgt) {
  sc.children.forEach(child => {
    child.position.copy(child._origPos);
    child.position.addScaledVector(child._explodeDir, tgt);
  });
}
